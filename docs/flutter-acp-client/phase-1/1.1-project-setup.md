# Задача 1.1 — Структура проекта и зависимости

## Цель

Настроить структуру папок (Clean Architecture) и зависимости внутри существующего модуля `apps/codelab_desktop`.

## Предварительные требования

- Flutter SDK >= 3.19
- Dart SDK >= 3.3
- Понимание базовой структуры Flutter-проекта

---

## Шаг 1 — Использование существующего проекта

**Не создавай новый проект.** Все изменения применяются к `apps/codelab_desktop`.

```bash
cd apps/codelab_desktop
```

Существующая структура `lib/`:
```text
lib/
├── main.dart
└── app/
    ├── app.dart
    ├── dialogs/
    ├── mock/
    ├── models/
    ├── navigation/
    ├── screens/
    ├── shell/
    ├── state/
    ├── theme/
    └── widgets/
```

---

## Шаг 2 — Структура директорий (Clean Architecture)

Добавь следующие директории внутри `apps/codelab_desktop/lib/`:

```text
lib/
├── main.dart                          # Entry point (уже существует)
├── app/                               # Существующая структура (сохранить)
│   ├── app.dart                       # CodeLabAppBootstrap
│   ├── dialogs/
│   ├── mock/
│   ├── models/
│   ├── navigation/
│   ├── screens/
│   ├── shell/
│   ├── state/
│   ├── theme/
│   └── widgets/
│
├── core/                              # Общие утилиты, DI, error handling
│   ├── di/
│   │   ├── app_module.dart
│   │   ├── session_module.dart
│   │   └── injection.dart
│   ├── error/
│   │   └── failures.dart
│   └── utils/
│       └── logger.dart
│
├── domain/                            # Чистая бизнес-логика
│   ├── entities/
│   │   ├── session.dart
│   │   ├── acp_message.dart
│   │   └── tool_call.dart
│   ├── repositories/
│   │   └── session_repository.dart
│   └── services/
│       └── transport_service.dart
│
├── application/                       # Use Cases и DTOs
│   ├── dto/
│   │   └── session_dto.dart
│   └── use_cases/
│       ├── initialize_use_case.dart
│       ├── create_session_use_case.dart
│       ├── load_session_use_case.dart
│       ├── list_sessions_use_case.dart
│       └── send_prompt_use_case.dart
│
├── infrastructure/                    # Реализации
│   ├── transport/
│   │   ├── websocket_transport.dart
│   │   ├── message_router.dart
│   │   ├── routing_queues.dart
│   │   └── background_receive_loop.dart
│   ├── services/
│   │   ├── acp_transport_service.dart
│   │   └── permission_handler.dart
│   ├── handlers/
│   │   ├── file_system_handler.dart
│   │   └── terminal_handler.dart
│   └── repositories/
│       └── in_memory_session_repository.dart
│
└── presentation/                      # BLoCs, экраны, виджеты (ACP-слой)
    ├── blocs/
    │   ├── session/
    │   │   ├── session_bloc.dart
    │   │   ├── session_event.dart
    │   │   └── session_state.dart
    │   ├── chat/
    │   │   ├── chat_bloc.dart
    │   │   ├── chat_event.dart
    │   │   └── chat_state.dart
    │   ├── permission/
    │   │   ├── permission_bloc.dart
    │   │   ├── permission_event.dart
    │   │   └── permission_state.dart
    │   └── terminal/
    │       ├── terminal_bloc.dart
    │       ├── terminal_event.dart
    │       └── terminal_state.dart
    ├── screens/
    │   ├── connect_screen.dart
    │   ├── session_list_screen.dart
    │   └── chat_screen.dart
    └── widgets/
        ├── message_bubble.dart
        ├── tool_call_card.dart
        ├── plan_panel.dart
        └── permission_dialog.dart
```

Создай новые директории командой:

```bash
cd apps/codelab_desktop
mkdir -p lib/core/{di,error,utils}
mkdir -p lib/domain/{entities,repositories,services}
mkdir -p lib/application/{dto,use_cases}
mkdir -p lib/infrastructure/{transport,services,handlers,repositories}
mkdir -p lib/presentation/{blocs/{session,chat,permission,terminal},screens,widgets}
```

> **Важно:** Существующая папка `lib/app/` НЕ удаляется и НЕ перемещается. Она содержит UI-оболочку приложения (`CodeLabAppBootstrap`, `DialogHost`, `HomeScreen`, `SessionScreen`). Новые папки (`core/`, `domain/`, `application/`, `infrastructure/`, `presentation/`) добавляются рядом с `app/`.

## Шаг 3 — Настройка pubspec.yaml

Обнови `apps/codelab_desktop/pubspec.yaml`, добавив необходимые зависимости.
Не заменяй файл целиком — сохрани существующие настройки Flutter и `fluent_ui`, добавь новые зависимости:

```yaml
name: codelab_desktop
description: "CodeLab Desktop — ACP Client"
publish_to: 'none'
version: 1.0.0+1

environment:
  sdk: ^3.11.5

dependencies:
  flutter:
    sdk: flutter

  # === Существующие зависимости (сохранить) ===
  cupertino_icons: ^1.0.8
  fluent_ui: ^4.15.1
  go_router: ^17.2.2
  cherrypick: ^3.0.2
  cherrypick_annotations: ^3.0.2

  # === Новые зависимости для ACP Client ===
  # State Management
  flutter_bloc: ^8.1.6
  bloc: ^8.1.4

  # Data models (иммутабельные классы + JSON)
  freezed_annotation: ^2.4.1
  json_annotation: ^4.9.0

  # WebSocket
  web_socket_channel: ^3.0.1

  # Functional programming (Either для ошибок)
  fpdart: ^1.1.0

  # Logging
  structured_log: ^0.1.0

  # UUID генерация
  uuid: ^4.4.2

  # UI Components (общая библиотека проекта)
  codelab_ui_components:
    path: ../../packages/codelab_ui_components

  # Дополнительно
  equatable: ^2.0.5
  rxdart: ^0.28.0

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^6.0.0
  go_router_builder: ^4.3.0
  build_runner: ^2.14.1

  # Code generation
  freezed: ^2.5.7
  json_serializable: ^6.8.0
  cherrypick_generator: ^3.0.0

  # Testing
  mocktail: ^1.0.4
  bloc_test: ^9.1.7
```

Установи зависимости:

```bash
cd apps/codelab_desktop
flutter pub get
```

## Шаг 4 — Настройка analysis_options.yaml

Обнови `apps/codelab_desktop/analysis_options.yaml`, добавив исключения для генерируемых файлов:

```yaml
include: package:flutter_lints/flutter.yaml

analyzer:
  errors:
    missing_required_param: error
    missing_return: error
  exclude:
    - "**/*.g.dart"
    - "**/*.freezed.dart"

linter:
  rules:
    - always_declare_return_types
    - avoid_dynamic_calls
    - avoid_print
    - prefer_const_constructors
    - prefer_final_fields
    - prefer_final_locals
    - sort_constructors_first
    - unawaited_futures
    - avoid_redundant_argument_values
    - require_trailing_commas
```

## Шаг 5 — Настройка build.yaml

Создай файл `apps/codelab_desktop/build.yaml` для настройки code generation:

```yaml
targets:
  $default:
    builders:
      cherrypick_generator|cherrypick_builder:
        enabled: true
```

## Шаг 6 — Проверка

Запусти анализатор из корня рабочей директории:

```bash
melos run analyze
```

Или напрямую из модуля:

```bash
cd apps/codelab_desktop
flutter analyze
```

Убедись, что нет критических ошибок. Ошибки о несуществующих файлах нормальны на этом этапе.
