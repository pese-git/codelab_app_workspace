# Задача 1.3 — Error Handling (Either / Failures)

## Цель

Создать единообразную систему обработки ошибок через типизированные классы `Failure` и функциональный тип `Either<Failure, T>` из пакета `fpdart`.

## Концепция

В Python-референсе Use Cases бросают исключения (`RuntimeError`, `ValueError`). В Flutter-архитектуре лучше использовать **Either** — тип, представляющий либо ошибку (`Left`), либо успешный результат (`Right`). Это делает обработку ошибок явной и убирает необходимость в `try/catch` везде.

```dart
// Вместо:
try {
  final result = await useCase.execute(request);
} catch (e) { ... }

// Используем:
final result = await useCase.execute(request);
result.fold(
  (failure) => /* обработать ошибку */,
  (data) => /* использовать данные */,
);
```

## Шаг 1 — Создание типов ошибок

Создай файл `lib/core/error/failures.dart`:

```dart
import 'package:equatable/equatable.dart';

// Базовый класс для всех ошибок приложения
abstract class Failure extends Equatable {
  final String message;
  final String? code;

  const Failure({required this.message, this.code});

  @override
  List<Object?> get props => [message, code];
}

// Ошибки транспортного слоя (WebSocket, сеть)
class TransportFailure extends Failure {
  const TransportFailure({required super.message, super.code});
}

// Ошибки протокола ACP (JSON-RPC ошибки от сервера)
class ProtocolFailure extends Failure {
  final int? errorCode;

  const ProtocolFailure({
    required super.message,
    this.errorCode,
    super.code,
  });

  @override
  List<Object?> get props => [...super.props, errorCode];
}

// Ошибки сессии (сессия не найдена, не инициализирована)
class SessionFailure extends Failure {
  const SessionFailure({required super.message, super.code});
}

// Ошибки аутентификации
class AuthFailure extends Failure {
  const AuthFailure({required super.message, super.code});
}

// Ошибки файловой системы
class FileSystemFailure extends Failure {
  final String? path;

  const FileSystemFailure({required super.message, this.path, super.code});

  @override
  List<Object?> get props => [...super.props, path];
}

// Ошибки терминала
class TerminalFailure extends Failure {
  final String? terminalId;

  const TerminalFailure({
    required super.message,
    this.terminalId,
    super.code,
  });

  @override
  List<Object?> get props => [...super.props, terminalId];
}

// Неожиданные ошибки (обёртка над Exception/Error)
class UnexpectedFailure extends Failure {
  const UnexpectedFailure({required super.message, super.code});
}

// Ошибки валидации входных данных
class ValidationFailure extends Failure {
  const ValidationFailure({required super.message, super.code});
}

// Timeout
class TimeoutFailure extends Failure {
  const TimeoutFailure({
    super.message = 'Operation timed out',
    super.code,
  });
}
```

## Шаг 2 — Вспомогательные утилиты

Добавь в файл `lib/core/error/failures.dart` утилиты для работы с Either:

```dart
import 'package:fpdart/fpdart.dart';

// Типовые алиасы для удобства
typedef EitherFailure<T> = Either<Failure, T>;
typedef FutureEither<T> = Future<Either<Failure, T>>;

// Хелпер для оборачивания исключений в Failure
EitherFailure<T> handleException<T>(
  Object exception,
  StackTrace stackTrace,
) {
  if (exception is ProtocolFailure ||
      exception is TransportFailure ||
      exception is SessionFailure) {
    return left(exception as Failure);
  }

  return left(
    UnexpectedFailure(message: exception.toString()),
  );
}
```

## Шаг 3 — Пример использования в Use Case

Вот как будет выглядеть Use Case с Either:

```dart
// lib/application/use_cases/initialize_use_case.dart
import 'package:fpdart/fpdart.dart';

import '../../core/error/failures.dart';
import '../../domain/services/transport_service.dart';
import '../dto/session_dto.dart';

class InitializeUseCase {
  final TransportService _transport;

  InitializeUseCase(this._transport);

  Future<Either<Failure, InitializeResponseDto>> execute() async {
    try {
      await _transport.connect();
      final result = await _transport.initialize();
      return right(result);
    } on TransportFailure catch (f) {
      return left(f);
    } on ProtocolFailure catch (f) {
      return left(f);
    } catch (e) {
      return left(UnexpectedFailure(message: e.toString()));
    }
  }
}
```

## Шаг 4 — Пример использования в BLoC

```dart
// В BLoC event handler:
on<InitializeRequested>((event, emit) async {
  emit(const SessionState.loading());

  final result = await _initializeUseCase.execute();

  result.fold(
    (failure) => emit(SessionState.error(failure.message)),
    (data) => emit(SessionState.initialized(data)),
  );
});
```

```dart
// lib/core/error/failures.dart (добавить)

ProtocolFailure fromJsonRpcError({
  required int code,
  required String message,
}) {
  return ProtocolFailure(
    message: message,
    errorCode: code,
    code: 'JSONRPC_$code',
  );
}
```

## Важные правила

1. **Use Cases всегда возвращают `Either<Failure, T>`** — никаких бросков исключений наружу.
2. **Infrastructure слой может бросать исключения** — но они должны быть поймать в Use Cases и преобразованы в `Failure`.
3. **BLoC обрабатывает `Either`** через `fold()` — никакого `try/catch` в BLoC.
4. **Логируй исключения перед оборачиванием** — чтобы не потерять stack trace.
